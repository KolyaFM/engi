# Энги 2.0 — обновление

## Опубликовать поверх работающего приложения

1. В работающей Энги сохраните резервную копию прогресса.
2. Распакуйте архив. Замените файлы в локальном проекте содержимым папки `engi`, сохраняя свою папку `.git`, если она есть. Файлы `src`, `tests`, `scripts`, `package.json`, `pnpm-lock.yaml`, `vite.config.ts`, `public` и `.github` должны лежать в корне репозитория, без дополнительной вложенной папки `engi`.
3. Сохраните изменения в той же ветке `main` того же репозитория GitHub. Базовый адрес по-прежнему `/engi/`. Создавать новый репозиторий или менять адрес не нужно.
4. В Actions дождитесь успешного нового запуска `Deploy Engi to GitHub Pages`. Если запуск не появился: Run workflow → main.
5. Закройте старую вкладку/установленную PWA, откройте приложение онлайн и примите обновление в спокойный момент. В новой версии рядом с названием появляется «2», а в настройках указано «Энги 2.0».
6. Если старая версия держится в кэше, сначала проверьте свежую версию в частной вкладке Safari. Основную базу сайта не очищайте. Старая оболочка может не показать предложение обновления сразу; полностью закрытые вкладки и повторное открытие онлайн позволяют worker завершить переход.

Исправление выбора `.engi` сохранено: у загрузчика нет `accept`, скрывающего неизвестные расширения на iPhone.

## Что изменилось

- Непрерывная Study Feed вместо остановки на 15 вопросах. Один тап отвечает на Choice, Categorize и Missing; правильный ответ переходит дальше автоматически. Ошибка показывает выбранный и правильный ответы и остаётся до следующего действия.
- Recall-Reveal заменяет текстовый ввод. Rapid Match/Categorize проверяют один объект за раз с отдельным атомарным сохранением. Timeline: одна шкала, отправка по отпусканию. Sort: до четырёх строк, pointer drag и доступные кнопки вверх/вниз.
- Локальные типы объектов и поля. Можно создать «Место рождения», связать президента с городом и использовать новое поле без изменения кода. Текстовые поля по умолчанию не тестируются. Неоднозначные single-answer задания отбрасываются, сами знания сохраняются.
- Редактор названий, других названий, типов, тегов, фактов, источников, проверки и короткого контекста. Создание связанного объекта, загрузка изображений, выбор основного и обучающего изображения. Входящие связи, локальный поиск по значениям и связям.
- Компоновщик сначала выбирает потребность и цель памяти, затем допустимый способ проверки. Начальная смесь due/weak/new/challenge 55/20/15/10, с повышением доли due при нагрузке. Кулдауны целей, объектов и ответов; вызовы не подряд. Буфер до 12, пополнение ниже 6, предзагрузка четырёх медиа.
- Ошибки дают отложенные repair probes после других карточек. Быстрый repair существующей памяти до срока не пересчитывает FSRS. Новая ошибка pretest не создаёт Again. Все успешные проверки ограничены Good, автоматического Easy нет. Путаницы влияют на варианты и затухают после успешных различений.
- Миграция Dexie v1→v2 добавляет `propertyDefinitions` и `entityTypes` и индекс входящих связей. Старые Memory IDs сохранены, история append-only. Старые сессии закрываются как завершённые, новая лента поддерживает восстановление текущего места.
- Импорт пакетов v1 и v2. Поля и типы v2 являются данными. ZIP обрабатывается отдельным worker в браузере; проверки путей, хешей, MIME и ссылок сохраняются. Импорт можно отменить до атомарной фиксации. При ошибке старая база сохраняется.
- Ручные записи и правки имеют `origin`/`userModified`. Обновление пакета сохраняет локальное значение и помечает upstreamConflict; архивирование не удаляет историю. Изменение Fact.value инвалидирует только его состояния, переименование/источник/теги — нет.
- `.engi-backup` v2 включает прогресс, историю, настройки, личные знания, определения, теги, ручные правки и собственные изображения. Зависимые объекты включаются для восстановления ссылок. Изображения пакетов остаются в .engi. Старые копии v1 принимаются.
- Охват рассчитывается по canonical Memory Targets независимо от Choice. Прогресс показывает категории, поля, горизонты 7/30/90 дней и путаницы.
- Проверка обновлений при регистрации worker, возвращении в приложение, восстановлении сети и раз в пять минут. В настройках есть ручная проверка. Предложение обновить скрыто во время обучения.

## Модель знаний

Entity — объект; EntityTypeDefinition — его тип; Fact.key — ID поля; Fact.valueEntityId либо literal — значение. Entity-valued facts являются направленными связями. Tags организуют подборки и не превращаются в факты.

PropertyDefinition хранит стабильный `id`, название, `valueKind`, допустимые типы subject/target, one/many, `learnable`, обратное направление и настройки форматов auto/on/off. Встроенные IDs created_by, creation_date, presidency_start, presidency_end, party, movement, birth_date, invented_by, event_start, capital, definition сохранены.

Старые состояния `entity:<id>:image_to_name`, `fact:<id>:image_to_created_by`, `<property>_to_year` и остальные встроенные ключи сохраняются. Новые поля используют стабильные `property:<id>:forward:<cue>` и `property:<id>:reverse`.

В v1 не было достаточной provenance-информации для восстановления различия между оригиналом пакета и прежней ручной правкой. Поэтому существующие пакетные строки при миграции консервативно защищаются как userModified. Это предотвращает потерю старых исправлений; последующие upstream-различия видны как конфликты.

## Проверки

- `pnpm test`: 1575 сгенерированных и проверенных заданий, все 7 форматов; 18 тестов persistence, migration, schema, dynamic generation, overlay merge, backup, atomic answer, cooldowns, delayed retry и продолжения ленты.
- `pnpm build`: TypeScript и production build проходят, shell и worker собираются.
- Production bundle сохранён в dist.

Реальный iPhone пока не проверен. Требуется ручной приёмочный прогон: 20 правильных Choice ≈20 тапов; ошибка остаётся; Recall не вызывает клавиатуру; Timeline/Sort работают пальцем; импорт .engi v1 через worker; отмена большого импорта; авиарежим; закрыть/открыть ленту; повторный импорт поверх ручной правки; backup/restore собственного изображения; увеличение текста; Reduced Motion; обновление без потери базы.

Расширенные эксперименты Before/After, Which is closer, Find target и Odd one out не добавлены: это разрешённые дальнейшие варианты, не обязательные форматы этой итерации. A/B эксперименты и измерение p95 на телефоне требуют реального устройства и накопленных событий. Данные событий (reason, latency, evidence, selfReport, fsrsUpdated) доступны локально.
