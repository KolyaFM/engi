# Endless study

The normal UI starts an endless goal feed. Existing bounded service sessions remain supported for callers, historical sessions and schedule simulations. A daily new-card preference remains the target and zero disables automatic new admission.

When scheduled work or repair is available, run it before filler. After the daily target, admit one additional goal as soon as it is playable. No mandatory six-screen filler interval separates admissions. Successful first checks waiting for FSRS do not occupy admission capacity. Three unresolved initial failures pause new admission until fresh repair releases attention. Extra admission is transactional and is committed only if it actually produces learning or an intro. Daily budget, admission capacity and total FSRS learning workload are independent.

Practice is organized into invisible persisted six-task rounds with up to three knowledge keys. Use the existing validated generators, image selection, group mechanics and exact goal memory. Respect selected scope and format. Practice cannot update FSRS or independent day counts. Persist its first failures as errors to be repaired on a fresh task; practice successes cannot close existing errors.

Reserve the nearest upcoming check across recognition/recall of the same knowledge. Practice must not disclose that knowledge when another playable knowledge exists. Keep the reservation across rounds until it is checked or invalidated, so repeated filler cannot continually postpone every check. When content contains only one playable knowledge, practice may continue conservatively without pretending it was delayed recall.

Use a shared session history for introductions, learning, repairs and games. Rounds focus practice, without preventing scheduled work from interrupting. No automatic extra budget for explicit free-practice sessions. Empty or unsupported content can still show an actionable explanation; do not invent questions.

No schema migration, progress reset, dependencies, artificial recall grading or global FSRS interval changes. Existing backup metadata remains compatible.

The new design initially keeps existing goal-based daily counting; changing the historical counting unit requires a separate migration. Ten can be selected in the existing daily preference; do not overwrite user settings.
