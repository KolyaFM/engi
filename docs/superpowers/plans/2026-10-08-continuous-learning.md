# Continuous learning implementation plan

> Execution: superpowers:executing-plans, inline in the authorized checkout.

**Goal:** A continuous varied feed with real five-minute confirmations and honest per-property evidence.
**Architecture:** Acquisition owns initial deadlines, FSRS owns graduated deadlines. A common selector balances available work, introductions and safe contextual practice; grouped answers retain individual evidence.
**Spec:** `docs/continuous-learning-design-2026-10-08.md`
**Tech stack:** TypeScript, Dexie, React, node:test, Playwright.

## Constraints

Preserve previous FSRS memory, backup compatibility, daily object budget, property counters and idempotent answers. No blocked question or waiting screen when material is available. Approximate dates/order remain practice.

## Tasks

- [x] Test and implement five-minute acquisition confirmations; retain future deadlines on read and gate early evidence. Files: acquisition, lifecycle service, acquisition evidence, acquisition tests.
- [x] Test and implement paced admission, workload limits on first checks, object/format fairness and due servicing. Files: lifecycle-feed-service, new continuous-feed policy, lifecycle tests.
- [x] Integrate safe timeline/sort/missing practice in mixed feed; honor explicit formats; preserve matching evidence and avoid forced groups. Files: lifecycle feed/composer/compiler tests.
- [x] Adapt old simulations to timestamp-based confirmations; test frozen-clock continuity, fast/slow sessions, rich objects, repairs, restart and limited material.
- [x] Run full tests/build and relevant browser checks; update trace and audit with measured results.

## Review focus

Future deadlines survive restart; waiting units do not block admissions. Group members cannot bypass deadlines. Practice cannot credit acquisition or FSRS. Rich objects cannot cause permanent admission starvation. Suspended/scoped knowledge cannot leak through diagnostic generation.

No commit, push or data migration on the user's live database is part of this task.
