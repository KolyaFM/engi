# Mobile study smoke check

Run `pnpm build`, then `pnpm test:smoke:mobile`. Install the browser once with
`pnpm exec playwright install chromium`. On machines with a separately installed
browser, set `ENGI_BROWSER_PATH` to its executable. Ports 4175 and 5175 must be free;
`ENGI_SMOKE_PORT` and `ENGI_GESTURE_PORT` override them.

For a larger profile, set `ENGI_SMOKE_ENTITIES=80` (8–200 objects),
`ENGI_SMOKE_CPU=4` (Chromium CPU throttling, 1–8), and
`ENGI_SMOKE_OUTPUT=artifacts/mobile-profile/80`. Defaults keep the CI scenario small.
Run profiles sequentially: fixture paths and default server ports are shared.

The runner creates two synthetic, overlapping `.engi` archives and starts isolated
preview and development servers. It uses a fresh browser context; personal data
and installed decks are not accessed. Servers are stopped on completion or failure.

## What is checked

The production scenario imports both archives through the normal interface, verifies
that the still-visible import notification cannot intercept the start button, selects
a deck, introduces objects and answers tasks generated by the real scheduler. It
checks property-based learning counts, a wrong answer followed by a later repair,
and persistence across reloads during introduction, revealed recall and chronology.
Property selections are saved and checked after reload. Deleting the overlapping
pack must preserve shared content; deleting the last pack must remove content,
sessions, review history and cached images.

Separate component checks use actual touch events for curved horizontal swipes,
vertical scrolling, interruption, a second finger, both swipe directions and recall
timer/disabled states. These run against development modules; they are distinct
from the production scenario and do not exercise scheduler selection.

## Reports and limits

`artifacts/mobile-smoke/` contains `report.json`, `runner.log`, a Playwright trace
and a completion or failure screenshot. The report includes format/presentation
counts, transition durations, median/P95/max and long main-thread tasks. It also
compares per-key and indexed-range state reads against identical saved goal IDs,
requiring equivalent results. Reloads
retain prior diagnostic stages. Read durations as whole UI actions: matching and
chronology include multiple player actions; the deliberate wrong-answer turn
includes a retry. Images must finish loading before a transition is considered ready.

The synthetic fixture has a fixed creation date. The browser seeds `Math.random`
and generates deterministic UUIDs with a counter retained across reloads; no tasks
or database progress are injected. Browser time is paused during the second import
so the notification regression cannot pass simply because the toast expired.
Format assertions verify observed coverage rather
than a fixed question list. Browser time advances for recall and delayed learning
confirmations; timing samples are diagnostics, not device performance thresholds.
This is Chromium mobile emulation, not a replacement for testing Safari on an iPhone.

GitHub Pages CI runs this check after unit tests and the production build. Failure
blocks publication and uploads reports for inspection. Performance limits should
be calibrated with repeated runs on a fixed device and realistic large packs.
