# Проверка ритма действующей ленты

Дата: 23 октября 2026. Проверен main `0c2f77f` без изменения продуктового кода.
Синтетические правильные ответы, реальный trainer service, fake-indexeddb и
виртуальные часы. Это воспроизведение алгоритма, не наблюдение личного занятия
пользователя и не эксперимент по запоминанию человеком.


Результаты: 14/14 и 33/33; всего 47 успешных тестов. Полный suite/build не
повторялись: в этом аудите менялись только документы. Логи остаются локально
в artifacts/feed-design-baseline.log и artifacts/feed-mechanics-baseline.log.

Счётчик match в четырёхобъектном отчёте нельзя напрямую считать групповым:
этот тест сохраняет recipe.format. Богатый feed-variety отдельно переименовывает
одиночный match/categorize в single-choice. В длинном богатом прогоне:
51 choice, 18 single-choice, 18 recall, 8 порядков, 8 flip-grid,
9 конвейеров, 1 категоризация, 3 групповых сопоставления.

В богатом прогоне repeatWithAlternative=0 и adjacentProperties=0. Это полезные
проверки непосредственных повторов; они не доказывают правильную долю форматов.
33 дополнительных проверки подтверждают работу групповых ответов, сохранение
черновиков, отсутствие двойного зачёта, достижимость периодов при быстром старте
и одинаковую последовательность с диагностикой и без неё. Проверка отдельного
генератора не доказывает его частоту во всей смешанной ленте.

## Причины и пробелы измерений

1. `lifecycle-feed-service.ts`: в практике knowledgeFormatRank сравнивается
   раньше formatRank. Выравнивание счётчиков форматов одного знания даёт
   примерно половину recall, не редкую проверку воспроизведения.
2. Группы строятся из selected, практика использует атомарный practicePool.
   Так fallback теряет часть доступных взаимодействий. Нельзя говорить, что
   любая группа всегда доступна: отдельно проверяются фактические раскрытия,
   резерв подтверждения и достаточность совместимых объектов.
3. Ранние return для self-check/recall/периодов/хронологии обходят общее
   сравнение. Разрешение формата и решение показать его смешаны.
4. Разновидность изображения может измениться при materialize. Статистика
   recipe.format не всегда совпадает с тем, что видел игрок.
5. Тесты распределения объектов не имеют критерия максимальной доли recall.
   Их зелёный результат пропустил плохую ленту; новые критерии должны проверять
   ритм и доступность вместе, не требовать равных количеств каждого формата.
6. Лог `not-reached` сообщает место выхода, но не доказывает, что оставшийся
   генератор был бы валиден. Для аудита вытеснения нужно отдельное ограниченное
   построение альтернатив в общей политике, не догадка по этой метке.
