# Исправление этапа 2: независимый зачёт в действующей ленте

> Отчёт предыдущего этапа. Последующее изменение момента коммита первого ответа, актуальные проверки и границы описаны в `STUDY_CORE_FIRST_ANSWER.md`.

Дата проверки: 8 октября 2026 года. Этот отчёт заменяет выводы исходного `STUDY_CORE_STAGE2.md` о готовности интеграции.

## Исправлено

1. Подтверждённые справочные факты с `learnable: false` можно показывать в Object Intro. Они участвуют в проверке ревизий, но не создают цели памяти. Завершение знакомства больше не падает из-за такого контекста.
2. Нормальный показ ответа после стадии размышления в Recall сохраняет право владельца попытки на явно обозначенный самоотчёт. Раннее раскрытие, подробности и источник до первого ответа это право снимают. Раскрытие ответа всё ещё блокирует другую открытую попытку затронутой цели.
3. Обработчик завершения эпизода видимости привязан к экрану, который создал эпизод. Перерисовка следующей карточки не подменяет владельца старого события `end`.
4. Право на зачёт теперь проверяется перед действующим коммитом памяти, а не только записывается в аудит. Не независимый ответ не меняет FSRS, освоение, калибровку и счётчики памяти, не создаёт долг исправления и не увеличивает дневной счётчик самостоятельных проверок. Событие практики сохраняется.
5. Первый неправильный выбор фиксируется сразу. Подсказка, открытая после него, не стирает независимую ошибку; исправленный выбор не превращает её в успех. Повторная отправка не делает второй коммит.
6. Изменение содержания между первым выбором и исправлением блокирует коммит в действующую память. Историческая попытка прежней ревизии сохраняется, но карточка получает `invalid_content`, а не ошибку пользователя.
7. Для полного набора используется единая оценка: частичный выбор не даёт успешного свидетельства отдельным членам набора.
8. Ошибка записи при подготовке контракта не маскируется под ошибку содержания: она прерывает транзакцию.

## Границы реализации

- В ленте по-прежнему одно расписание памяти: существующий `learningState`. Новое ядро вызывается с `applyMemory: false`, но его результат уже управляет допустимостью существующего коммита (`eligibility-gate`). Это промежуточный переход, а не завершённая миграция к памяти новых целей.
- Полный набор имеет одну цель в контракте, однако его результат пока проецируется в существующие записи отдельных членов. Эти записи нельзя считать несколькими независимыми успехами. Переход к одной записи памяти набора — следующий отдельный этап.
- Дневной план «Повторить / Закрепить / Новое», новый подбор следующего задания и отдельное хранилище журнала ещё не внедрены. Уведомление о 15 проверках больше не заявляет, что дневная цель выполнена.
- Пауза после раскрытия в 60 секунд остаётся рабочей настройкой, а не доказанным оптимумом.
- Рост журнала, очистка незавершённых попыток, производительность событий видимости и явно описанные раскрытия в свободных текстах требуют дальнейшей проверки.

- `npm run build`: успешная проверка TypeScript и production-сборка. Есть предупреждение сборщика о крупных чанках; оно не устранено этим исправлением.

## Запуск

`node_modules` в архиве не нужен. В среде с Node.js версии из `package.json` установить зависимости командой `pnpm install --frozen-lockfile`, затем выполнить `pnpm test`, `pnpm build` и `pnpm dev`. Для браузерного набора нужен Chromium, установленный для версии Playwright проекта, либо путь `ENGI_BROWSER_PATH` к совместимому браузеру.
