# Настоящие групповые задания

Продолжение FEED_PERFORMANCE.md. Здесь добавлены полноценные match и categorize, а не новые названия обычного выбора одной кнопкой.

## Поведение

В смешанной ленте могут появляться группы из 2–3 объектов. Для каждого объекта игрок выбирает ответ. В match ответы используются по одному разу: перенос занятого ответа снимает его с предыдущего объекта. Последняя пара не заполняется автоматически. В categorize один ответ можно назначить нескольким объектам. Вопрос указывает свойство, по которому требуется сопоставление.

После заполнения всех строк игрок нажимает «Проверить». До этого промежуточные назначения сохраняются как черновик и не оцениваются. Результат показывает верные и неверные строки и правильные ответы. Переход выполняется кнопкой «Дальше», чтобы успеть рассмотреть несколько исправлений. Сохранённый черновик и результат восстанавливаются при возврате.

Изображения показываются отдельно для каждого объекта. Вопрос считается доступным для ответа и учёта видимости только после готовности всех требуемых изображений. Неработающее изображение позволяет пропустить группу без зачёта.

## Отбор и прогресс

- Группы строятся из уже доступных одиночных кандидатов с одинаковым форматом, свойством, направлением и типом подсказки. Новые и повторяемые цели собираются в отдельные группы.
- Группа не включает цель, ожидающую срока FSRS или окончания паузы после раскрытия ответа. Состав будущих групп не заставляет повторять заранее.
- Размер новой группы не превышает оставшийся бюджет дня и свободные места первого обучения. Если осталось одно место, новой группы нет.
- Match требует разных ожидаемых ответов. Categorize допускает повторяющиеся ожидаемые ответы. Несколько связей одного объекта в одну группу не включаются: ключ ответа должен однозначно обозначать строку.
- Одинаковые видимые имена или одинаковые изображения у разных строк исключают такую группу. Неоднозначные варианты ответа проходят прежний preflight.
- У каждой связи остаётся собственная recognition-цель и память FSRS. Ошибка в одной строке не отменяет правильную строку. Средний балл карточки используется для отображения; он не определяет оценки памяти участников.
- Первый полный ответ оценивается один раз. Повторная отправка, исправленный ответ и повторное открытие результата не запускают FSRS ещё раз.
- Подсказка о связи в bijective match блокирует независимый зачёт всей группы: остальные ответы можно вывести исключением. Перестановки ответов не являются статистически независимыми попытками. Групповой формат не засчитывает свободное воспроизведение.
- Если после показа изменился факт или отключён любой участник, вся устаревшая группа завершается без нового зачёта. Если другая карточка уже повторила участника и перенесла его срок, память этого участника не обновляется второй раз; остальные допустимые участники оцениваются.

## Ограничение вычислений

Не перечисляются все сочетания объектов. Строится до 32 групп на формат; у каждой точки начала просматривается до 64 соседних кандидатов. Порядок обхода перемешивается, чтобы бюджет генерации не закреплялся за первыми объектами и свойствами. Полный доступный набор целей остаётся представлен одиночными кандидатами. Отсутствие группового варианта не убирает цель из обучения. Для диагностики добавлен отдельный этап `groups`.

Это ещё не реализация ленивой сборки всего пула. Большой новый набор продолжает требовать затрат на одиночные варианты.

## Проверки

- Все 6 перестановок трёх matching-ответов проверены через настоящий сервис и FSRS.
- Все 27 назначений трёх объектов в три категории проверены с отдельной оценкой каждой цели.
- Дополнительно проверено правильное распределение, в котором ожидаемые категории повторяются.
- Проверены незавершённый ответ, повтор одного ответа в match, сохранение черновика, подсказка, пропуск, повторная отправка, новая ёмкость 1/2/3, изменение не первого участника и защита участника с перенесённым сроком.
- Проверена серверная разметка компонента: восстановление выбранных ответов, исправления и ручной переход. Это не визуальный или интерактивный браузерный тест.
- Настоящая лента повторно моделировалась на 90 виртуальных дней в четырёх сценариях. Итоги: REAL_FEED_GROUPS_90_DAYS.json. Стенд принимает mapping-ответы и проверяет сроки зачёта, раскрытия, бюджет дня и предел трёх целей первого обучения.
- 227/227 тестов прошли; сборка TypeScript/Vite выполнена. Chromium в окружении отсутствует, поэтому расположение элементов и клики в браузере не объявляются проверенными.
- Интеграционные тесты дневного плана теперь фиксируют Date на местном полудне. При запуске за десять минут до местной полуночи прежние проверки ошибочно ожидали закрепление сегодня, хотя приложение корректно переносило его на завтра. Отдельные проверки полуночи сохранены; часы приложения не изменялись.

## Быстродействие и следующий шаг

FEED_LATENCY_GROUPS.json содержит измерения смешанной ленты при небольшой готовой очереди и большом количестве ещё не наступивших повторений. На 256 объектах переходы занимали 37–60 мс в этих шести ответах. Это сервисное время fake-indexeddb, без браузерной отрисовки и загрузки настоящих изображений.

FEED_LATENCY_GROUPS_FRESH.json проверяет полностью новый набор. Первые два перехода на 256 объектах заняли 419 и 407 мс. В первом переходе генерация одиночных кандидатов заняла 384 мс, групп — 8 мс. Во втором группы не могли поместиться в оставшиеся места; одиночные кандидаты всё равно заняли 386 мс. После заполнения мест первого обучения переход занял 24 мс.

Это подтверждает следующий приоритет: выбирать из лёгких описаний кандидатов, а полные варианты ответа и контракт собирать только для выбранного задания. Нужны проверки совпадения допустимых целей с текущим генератором, отсутствия голодания, изменения графа и неуспешной материализации. Ускорение для полностью новой большой колоды пока не объявляется завершённым.

Каталог остаётся каталогом целей; комбинации групп не создают дополнительные единицы прогресса. В небольшой очереди группа может появляться редко: лучше оставить корректное одиночное повторение, чем нарушить срок памяти ради разнообразия. Хронология и сортировка по-прежнему имеют прежний диагностический статус; в этом изменении им не добавлен зачёт точных дат.
