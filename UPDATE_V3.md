# Обновление до 3.0

1. В старой версии сохраните резервную копию.
2. Распакуйте новый исходный архив в отдельную папку. `node_modules` из старой папки копировать не требуется.
3. Выполните `pnpm install --frozen-lockfile`, `pnpm test`, `pnpm build`.
4. Для обновления сайта разместите содержимое `dist/` на прежнем адресе приложения. GitHub Pages workflow включён в исходники, публикация происходит вашим обычным способом.
5. При открытии на прежнем адресе IndexedDB обновится до v4. Существующие сущности, факты и ID прогресса сохранятся. Старые теги будут скопированы в самостоятельные колоды; теги также останутся.
6. Если адрес изменился, восстановите копию. Старые копии 1/2 не содержат все изображения пакетов — их нужно повторно импортировать. Новая полная копия 3 содержит все доступные изображения.

Новые колоды создавайте в формате `schemaVersion: 3`, см. `PACK_FORMAT_V3.md`. Старые пакеты 1/2 читаются прежним импортёром по техническим ID; объединения по именам для них нет. Для семантического импорта их нужно пересобрать в v3.

Версии различаются: приложение 3.0, пакет 3, база 4, резервная копия 3.

Архив содержит исходники, готовый `dist/`, примеры `.engi`, тесты и документацию. Деплой на сайт не выполняется автоматически при распаковке архива.
