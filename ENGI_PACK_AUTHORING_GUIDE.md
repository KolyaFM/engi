# Инструкция для ИИ: создание пакетов Engi

Этот документ можно целиком передать ИИ вместе с темой и пожеланиями пользователя. Он описывает декларативные пакеты **`.engi`, schemaVersion 3**. Если доступен репозиторий приложения, при расхождении ориентируйся на текущие `schema-v3.ts`, `semantic-merge.ts` и сборщик `build-engi-pack.mjs`.

## 1. Твоя задача и результат

Создай пригодную для импорта колоду знаний по запросу пользователя. Ты описываешь **объекты, их свойства, значения и источники**. Приложение само составляет вопросы, выбирает варианты ответа и планирует повторения.

Результат работы:

1. Готовый файл `название-пакета.engi`, если среда позволяет создавать файлы.
2. Исходники: `bundle.json` и используемые файлы `media/`.
3. Короткое пояснение: сколько объектов включено в обучение, какие свойства изучаются, что проверено и какие сведения остались непроверенными.

Не выдавай JSON или переименованный текстовый файл за готовый `.engi`. Не утверждай, что импорт проверен, если ты его не проверял. Если создание файлов недоступно, предоставь полный JSON и точные указания по сборке.

## 2. Сначала спроектируй знания

Перед сборкой определи:

- Какие объекты пользователь будет изучать: люди, картины, штаты, события и т. п.
- Какие свойства действительно полезно запоминать: год, автор, столица, флаг, расположение на карте.
- Какие объекты нужны только как значения или справочные ссылки: авторы картин, президенты событий, города-столицы.
- Какие типы объектов присутствуют и какие свойства применимы к каждому типу.
- Какие изображения будут основными, а какие — отдельными визуальными свойствами.

Если запрос достаточно конкретный, принимай разумные решения сам. Не превращай сборку в длинный опрос. Не добавляй случайные факты ради объёма и вопросы с очевидными ответами.

**Модель: объект → свойство → значение.** Например:

| Объект | Тип | Свойство | Значение |
|---|---|---|---|
| Луизианская покупка | Событие | Год события | 1803 |
| Луизианская покупка | Событие | Президент США | Томас Джефферсон — Человек |
| Алабама | Штат США | Флаг | Файл изображения |
| Звёздная ночь | Картина | Автор | Винсент ван Гог — Человек |

Не создавай отдельный объект «Луизианская покупка — год», если это свойство одного события. Не записывай весь рассказ об объекте одним обучаемым ответом.

## 3. Структура файлов

Исходная папка:

```text
my-pack/
  bundle.json
  media/
    alabama-map.png
    alabama-flag.png
```

Готовый `.engi` — обычный ZIP:

```text
bundle.json
manifest.json
media/alabama-map.png
media/alabama-flag.png
```

Файлы должны лежать **в корне архива**, без внешней папки `my-pack/`. Все JSON — UTF-8, без комментариев и завершающих запятых. Для пакета без изображений `media/` не нужна.

`.engi-backup` — резервная копия личной базы и прогресса. Это другой формат; не используй её структуру для создания колоды.

## 4. Корневой bundle.json

| Поле | Значение |
|---|---|
| `schemaVersion` | Обязательно число `3` |
| `name` | Обязательное название пакета, 1–200 символов |
| `description` | Необязательное краткое описание пакета, до 1000 символов |
| `properties` | Определения свойств; необязательно, но новые свойства необходимо объявить |
| `entityTypes` | Необязательные определения типов и их алиасов |
| `entities` | Обязательный массив объектов |
| `deck` | Колода и её участники; **всегда добавляй для обычного учебного пакета** |

Не добавляй произвольные корневые поля. Схема строгая.

**Не записывай внутренние идентификаторы приложения.** Ключи `id`, `entityId`, `factId`, `valueEntityId`, `tagId`, `mediaId`, `deckId`, `packId` запрещены в декларативном содержимом, в том числе внутри вложенных объектов. `packVersion` также не является допустимым полем bundle v3. Имена, типы, реальные алиасы и внешние идентификаторы используются вместо технических ID.

## 5. Объекты и ссылки

Объект в `entities`:

```json
{
  "name": "Луизианская покупка",
  "type": "Событие",
  "aliases": ["Louisiana Purchase"],
  "description": "США приобрели у Франции большую территорию к западу от Миссисипи. Это расширило страну и обеспечило контроль над важными торговыми путями.",
  "tags": ["История США", "Расширение территории"],
  "facts": [],
  "images": []
}
```

Допустимые поля объекта:

| Поле | Назначение |
|---|---|
| `name`, `type` | Обязательные строки, каждая 1–200 символов |
| `aliases` | Настоящие альтернативные названия, переводы и написания |
| `externalIds` | Словарь реальных внешних идентификаторов, например ключ `wikidata` |
| `qualifiers` | Реальные свойства для различения одноимённых объектов |
| `description` | Справочный текст до 4000 символов, открываемый по ⓘ |
| `facts` | Расширенные записи свойств, рекомендуемый способ описания знаний |
| `properties` | Краткий словарь значений; импортируется непроверенным |
| `completeProperties` | Свойства, для которых перечислен полный набор значений |
| `tags` | Тематические метки, строки |
| `images` | Объявления файлов изображений этого объекта |

Ссылка на другой объект — не его технический ID и не просто строка:

```json
{"name": "Томас Джефферсон", "type": "Человек"}
```

В ссылке допустимы только `name`, `type`, `aliases`, `externalIds`, `qualifiers`. Не помещай в ссылку `facts`, `description`, `images` или `tags`; для этого объяви объект отдельно в `entities`.

Справочные объекты разрешено объявлять без фактов и изображений. Не включай их в `deck.members`, если пользователь не должен учить их отдельно. Ссылки могут разрешаться и без отдельного объявления, но явные объявления обычно понятнее и проще проверяются.

Не придумывай внешние ID. Если надёжный идентификатор неизвестен, опусти `externalIds`.

## 6. Типы, теги и смешанные колоды

Тип определяет, **что это за объект**, а теги — его тематику. Используй устойчивые названия типов: `Человек`, `Картина`, `Событие`, `Штат США`. Не называй одного человека `Человек`, другого `Президент`, третьего `Персона`, если они должны участвовать в одинаковых заданиях.

Встроенные типы: `Человек`, `Картина`, `Страна`, `Город`, `Организация`, `Направление`, `Событие`, `Изобретение`, `Понятие`, `Фильм`, `Книга`, `Игра`. Новые типы поддерживаются; их можно объявить так:

```json
{"name": "Штат США", "aliases": ["US State"]}
```

Это элемент корневого `entityTypes`, а не объект для обучения.

Картины и художники могут находиться в одной колоде, но должны иметь разные типы. Укажи применимость свойств через `subjectTypes`: например, «Автор» относится к картинам, «Дата рождения» — к людям. Так настройки колоды смогут различать группы объектов.

Теги помогают подбирать тематически близкие объекты. Подходящие примеры: `История США`, `Французская живопись`, `Импрессионизм`. Не подменяй тегами свойства, которые пользователь должен запомнить. Не делай тысячу уникальных тегов по одному на объект. Теги — плоский массив строк; вложенные разделы в нём не задаются.

Сопоставление старается объединять совместимые сущности и учитывать их теги и пакет. Хронология может объединять разные типы. Один пакет не гарантирует, что все его объекты всегда попадут в одно групповое задание.

## 7. Определения свойств

Элемент корневого `properties`:

```json
{
  "name": "Год события",
  "valueType": "date",
  "multiple": false,
  "learnable": true,
  "subjectTypes": ["Событие"],
  "promptTemplates": {
    "forward": "В каком году произошло это событие?",
    "reverse": "Какое событие произошло в этом году?",
    "sort": "Расставьте события по времени."
  },
  "learning": {"timeline": "off", "missing": "off"}
}
```

| Поле | Формат и смысл |
|---|---|
| `name` | Обязательно, 1–200 символов |
| `aliases` | Необязательные названия того же свойства |
| `valueType` | Обязательно: `entity`, `text`, `number`, `date`, `boolean`, `image` |
| `multiple` | Несколько значений; по умолчанию `false` |
| `learnable` | Разрешено обучение; по умолчанию `true` |
| `subjectTypes` | Типы объектов, у которых есть это свойство |
| `targetTypes` | Типы объектов-значений, актуально для `entity` |
| `promptTemplates` | Тексты прямого, обратного и группового вопросов |
| `learning` | Разрешения форматов и направлений |
| `inverse` | Необязательное `{"enabled":true,"name":"Название обратного направления"}`; обычно не требуется |

Объявляй новое поле до его использования. Названия свойств глобальные: одно «Год события» не должно быть `date` в одном пакете и `text` в другом. Не используй алиас для объединения разных по смыслу свойств.

Встроенные свойства:

| Название | Тип значения | Несколько значений |
|---|---|---|
| Автор | `entity` | Да |
| Дата создания | `date` | Нет |
| Начало президентства | `date` | Нет |
| Конец президентства | `date` | Нет |
| Партия | `entity` | Нет |
| Направление | `entity` | Да |
| Дата рождения | `date` | Нет |
| Изобретатель | `entity` | Да |
| Начало события | `date` | Нет |
| Столица | `entity` | Нет |
| Определение | `text` | Нет; по умолчанию не обучаемое |

Встроенные поля имеют ограничения типов. Например, «Столица» применяется к `Страна`, а не автоматически к новому типу `Штат США`. Для штатов объяви самостоятельное поле **«Столица штата»** с `subjectTypes: ["Штат США"]` и `targetTypes: ["Город"]`. Не пытайся изменить тип значения или множественность встроенного поля ради одного пакета.

## 8. Факты, значения и точность

Факт — элемент `entities[].facts`:

```json
{
  "property": "Год события",
  "value": 1803,
  "source": {
    "kind": "url",
    "name": "National Archives: Louisiana Purchase Treaty",
    "url": "https://www.archives.gov/milestone-documents/louisiana-purchase-treaty"
  },
  "verification": "verified"
}
```

Допустимы `property`, `value`, `source`, `sources`, `verification`, `learnable`. `property` и `value` обязательны. Несколько источников задаются массивом `sources` с такими же объектами, как `source`.

| Тип | Правильный `value` | Примечание |
|---|---|---|
| `entity` | `{"name":"Томас Джефферсон","type":"Человек"}` | Для авторов, стран, категорий и связей между объектами |
| `text` | `"Короткий ответ"` | Для девиза, термина, краткой формулировки |
| `number` | `123` либо `{"value":123,"unit":"км"}` | Только конечное число, не строка с единицей |
| `boolean` | `true` либо `false` | Обратные вопросы для этого типа не формируются |
| `date` | `1803` или `"1803"` | Год |
| `date` | `"1803-04"` | Год и месяц |
| `date` | `"1803-04-30"` | Точная дата |
| `date` | `{"value":1803,"approximate":true}` | Приблизительно |
| `date` | `{"start":1803,"end":1804}` | Диапазон |
| `image` | `{"file":"media/alabama-flag.png"}` | Отдельное изображение-свойство |

Не записывай год строкой «1803 год» и дату как «30.04.1803». Используй поддерживаемый формат. Не придумывай день и месяц, если известен только год. Даты должны быть календарно допустимыми; отрицательные годы и запись «до н. э.» этим форматом не предусмотрены.

Не превращай неопределённость в ложную точность. Приблизительные даты и диапазоны не подходят для точного обратного вопроса и некоторых заданий на порядок.

Если факта нет, **не добавляй его**. Отсутствие президента у события 1776 года не заменяй ответом «Неизвестно» или случайным человеком.

Для справочного факта можно поставить `learnable: false`. Для длинного рассказа лучше использовать `description` объекта.

## 9. Источники и проверка

Один источник имеет поля `name`, необязательные `kind`, `url`, `locator`, `family`. Для внешнего источника используй `kind: "url"` и рабочую HTTPS-ссылку на конкретную страницу, поддерживающую утверждение. Одной ссылки на главную страницу сайта обычно недостаточно.

`locator` может уточнять страницу документа или раздел. `family` необязательно объединяет связанные источники. Значение `kind: "pack"` не разрешает локальный путь вместо HTTPS-ссылки. Без URL допустим только `kind: "manual"`.

| Статус | Как использовать |
|---|---|
| `unverified` | Не проверено; значение по умолчанию, не допускается к обычному обучению |
| `verified` | ИИ действительно сверил утверждение с указанным источником |
| `direct` | Подтверждено прямым источником; это тоже доверенный статус, а не обход проверки |
| `user_confirmed` | Пользователь явно подтвердил своё знание |
| `ambiguous`, `conflict`, `rejected` | Не использовать как готовые обучаемые ответы |

Для доверенного факта требуется источник. Не ставь `verified` только потому, что информация кажется знакомой. Не выдумывай URL, лицензии или результаты проверки. Если не можешь проверить, оставь `unverified` и сообщи об этом.

Для демонстрационных вымышленных сведений явно укажи, что это синтетический пример, и не выдавай их за исторические данные. `kind: "manual"` не является заменой исследованию реальных фактов.

## 10. Вопросы без повторов и двусмысленности

Название или изображение объекта уже находится над вопросом. Пиши:

- `forward`: «В каком году произошло это событие?»
- `reverse`: «Какое событие произошло в этом году?»
- Для художников: «Кто автор этой работы?» и «Какую работу написал этот художник?»
- Для штата: «В каком году этот штат вступил в Союз?» и «Какой штат вступил в Союз в этом году?»

Не повторяй название объекта в `forward` без необходимости. Плохой вариант: заголовок «Луизианская покупка» и затем вопрос «В каком году произошла Луизианская покупка?».

`promptTemplates` допускает только `forward`, `reverse`, `timeline`, `sort`. Единственная поддерживаемая подстановка — `{subject}`. Не используй `{answer}`, `{year}`, `{value}`, HTML или шаблонный программный код. В новом пакете длина `forward`, `reverse`, `timeline` — до 200 символов; `sort` — до 1000.

Задавай естественную формулировку для обратного направления явно. Она важнее технической заглушки приложения. При неоднозначности отключи `learning.reverse`, если обратный вопрос в этой теме вообще не имеет учебного смысла.

Одинаковый год у нескольких объектов допустим. Приложение исключает другие правильные ответы из неверных вариантов; не изменяй реальный год ради уникальности. Обратная самопроверка требует однозначного значения. Для обратных текстовых вопросов отображаемое значение не должно превышать 180 символов.

Для текста `reverse` значение свойства служит подсказкой. Для основных изображений и свойств-картинок приложение также умеет менять направление, но этот механизм не описывается отдельным массивом заданий.

## 11. Какие механики получатся из данных

Не записывай готовые задания, неправильные варианты, ответы пользователя или расписание в пакет.

| Данные | Возможные задания | Что подготовить |
|---|---|---|
| Основные изображения | Картинка → объект; название → выбор изображения; сопоставление | Несколько различимых объектов одного типа, минимум четыре для обратного выбора основных изображений |
| Связь `entity` | Прямой/обратный выбор, «вспомни», сопоставление | Несколько объектов и несколько разных значений |
| Повторяющиеся категории `entity` | Категоризация; для двух категорий — свайпы | Содержательные категории и достаточно объектов обеих сторон |
| `date`, `number` | Выбор, «вспомни», порядок | Не менее трёх разных значений; одинаковые единицы у чисел |
| Свойство `image` | Изображение-свойство → объект; объект → изображение-свойство; сопоставление | Явные факты `image` и объявленные файлы |
| Короткий `text` | Выбор и «вспомни» при соответствующем разрешении; обратные вопросы | Краткие различимые ответы |

Сопоставление использует не меньше трёх объектов. Двусторонний конвейер использует 3–6 объектов. Хронологический порядок — 3–5 объектов; в текущем интерфейсе ранние события находятся **снизу**, поздние — **сверху**. Для надёжного разнообразия готовь больше минимального количества объектов, а не только одну возможную группу.

Хронологические группы сейчас опираются на год даты. Не рассчитывай на различение двух событий одного года по месяцу или дню в задании на порядок. Точные даты при этом можно изучать обычными вопросами.

Механика появляется, когда есть достаточно подходящих знаний в текущей очереди. Часть объектов может быть уже известна, отключена пользователем или ещё не введена в обучение. Флаг `on` разрешает формат, но не отменяет эти ограничения и не задаёт частоту показа.

Самопроверка с переворачиваемыми карточками и представление в виде конвейера выбираются приложением. Не придумывай поля `self_check`, `conveyor`, `swipeDirections`, `minItems`, `tasks`, `questions`, `schedule` или `fsrs` в JSON.

## 12. Разрешения learning

У свойства `learning` поддерживаются:

- `forward`, `reverse`: логические `true` / `false`.
- `choice`, `recallReveal`, `match`, `categorize`, `timeline`, `sort`, `missing`: строки `auto`, `on`, `off`.

Отсутствие настроек обычно оставляет автоматический выбор. `recallReveal` написано именно так, не `recall_reveal`. Отдельного поля для длительности таймера нет.

Для короткого текстового свойства, которое пользователь должен учить, рекомендуется явно разрешить прямые форматы:

```json
{
  "name": "Девиз",
  "valueType": "text",
  "learnable": true,
  "subjectTypes": ["Штат США"],
  "promptTemplates": {"forward": "Какой девиз у этого штата?"},
  "learning": {"choice": "on", "recallReveal": "on", "reverse": false}
}
```

Если девизы длинные и плохо подходят для выбора, оставь `choice: "off"`. Для хронологии используй `sort`; старое `timeline` не означает новый отдельный формат ползунка, который нужно специально создавать в пакете.

Для точных дат (год, месяц или день) и чисел можно оставить только расстановку:
`learning: {"forward": false, "reverse": false, "sort": "on"}`.
Вопрос для этого задания задаётся в `promptTemplates.sort`. Такое свойство всё равно
появится в новой карточке и настройках колоды. Приблизительные даты и диапазоны
для расстановки не подходят: периоды используй в заданиях на полосы или границы.

У свойства с `multiple: true` приложение сравнивает все записанные числа или даты.
Например, номера 22 и 24 показываются у одного объекта как «22, 24» после проверки;
объект с номером 23 не попадёт с ним в одно задание, поскольку их порядок неоднозначен.
Не дублируй объект ради каждого номера. Числа с разными единицами не сравниваются.
Если требуется именно первое вступление в должность, явно задай отдельное точное
поле с первым годом: приложение не выводит это значение из периодов самостоятельно.
Расстановка подтверждает относительный порядок, а не память точного значения.

## 13. Основное изображение и изображение-свойство

**Основная картинка** показывает сам объект: портрет человека, репродукция картины, расположение штата на карте.

```json
{
  "file": "media/alabama-map.png",
  "role": "primary",
  "license": "Реальная лицензия изображения",
  "sourceUrl": "https://example.org/actual-image-page",
  "primary": true,
  "recognition": true
}
```

Это структурный пример: заменяй демонстрационные URL и лицензии реальными. В JSON объекта такое объявление находится в `images`.

**Флаг как свойство** требует трёх согласованных записей.

Определение в корневом `properties`:

```json
{
  "name": "Флаг",
  "valueType": "image",
  "multiple": false,
  "learnable": true,
  "subjectTypes": ["Штат США"],
  "promptTemplates": {"forward": "Какому штату принадлежит этот флаг?"}
}
```

Объявление файла в `images` того же штата:

```json
{
  "file": "media/alabama-flag.png",
  "role": "property",
  "license": "Реальная лицензия изображения",
  "sourceUrl": "https://example.org/actual-flag-page",
  "primary": false,
  "recognition": false
}
```

Факт в `facts` этого штата:

```json
{
  "property": "Флаг",
  "value": {"file": "media/alabama-flag.png"},
  "source": {"kind": "url", "name": "Источник о флаге", "url": "https://example.org/actual-flag-page"},
  "verification": "unverified"
}
```

После реальной проверки замени источник и статус. Добавь «Флаг» в `deck.learning.properties`.

Не заменяй карту флагом в основном изображении. Не ограничивайся вторым файлом в `images`: без факта `image` это не отдельное изучаемое свойство. Для визуальных свойств используй одно значение, `multiple: false`.

`recognition: false` исключает файл из общего узнавания объекта, но не отключает явный факт «Флаг». Основная картинка и флаг имеют разные знания и прогресс.

## 14. Требования к изображениям

- Только PNG, JPEG, WebP; не SVG, GIF, AVIF, PDF или ссылка на удалённый файл вместо вложения.
- Файл действительно скачан и вложен в архив. Его содержимое соответствует расширению и MIME.
- Путь начинается с `media/`, использует `/`, латиницу, цифры, `.`, `_`, `-`; до 200 символов. Используй расширения в нижнем регистре.
- Недопустимы абсолютные пути, `..`, обратные слеши, двоеточия, пробелы и кириллица в путях.
- У каждого изображения — реальная лицензия и HTTPS-страница источника. Наличие картинки в интернете само по себе не означает свободную лицензию.
- Не указывай `primary: true` у нескольких картинок одного объекта. Основную картинку задавай явно.
- Не добавляй одинаковые или почти неразличимые картинки как разные варианты узнавания. Оставляй достаточно разрешения для мобильного экрана; избегай чрезмерных прозрачных полей вокруг объекта.
- Не пиши правильный ответ поверх картинки, если это превращает узнавание в чтение подписи.

## 15. Несколько значений и одноимённые объекты

Если у произведения два автора, задавай **два факта**, не массив в `value` и не строку «А и Б». Свойство должно иметь `multiple: true`.

```json
{
  "name": "Учебная книга",
  "type": "Книга",
  "completeProperties": ["Автор"],
  "facts": [
    {"property": "Автор", "value": {"name": "Автор А", "type": "Человек"}, "verification": "unverified"},
    {"property": "Автор", "value": {"name": "Автор Б", "type": "Человек"}, "verification": "unverified"}
  ]
}
```

`completeProperties` утверждает, что список значений полный. Ставь его только после проверки полноты, иначе задание «выберите всех» будет оценивать неполный ответ как полный. Для известного полного списка авторов указывай его даже при одном авторе. Поддержка учебных полных многозначных наборов ориентирована на ссылки `entity`; не обещай такие же задания для массивов текста или изображений.

Для двух произведений с одним названием используй реальные уточнения:

```json
{
  "name": "Весна",
  "type": "Картина",
  "qualifiers": {"Автор": {"name": "Художник А", "type": "Человек"}}
}
```

Это пример ссылки с уточнением. В полном объявлении картины также опиши проверенные факты и полноту авторства. Уточнение должно совпадать с реальными свойствами объекта. Не выдавай разных людей за алиасы одного человека и не добавляй фиктивный год только для устранения совпадения названий.

## 16. События и справка по ⓘ

Для исторического события используй короткое название: «Покупка Аляски», «Луизианская покупка». Свойства: год, президент или другой содержательный участник, если это полезно для конкретной темы.

В `description` обычным человеческим языком объясни, что произошло и почему это событие важно. Можно упомянуть год и участников. Не делай обязательных секций «Контекст / Участники / Результат» и не добавляй мотивационных фраз.

Открытие описания по ⓘ не считается усвоением и не штрафует ответ. Описание — справочный текст, **не дополнительный факт для заучивания**. Не создавай отдельное поле «Описание», если нужен только этот механизм.

Различай события, которые легко перепутать: покупка территории и её превращение в штат; прокламация об освобождении и полная отмена рабства. Формулировка названия должна соответствовать проверяемому факту.

## 17. Состав колоды и настройки обучения

```json
{
  "name": "История США",
  "description": "События, годы и президенты",
  "members": [
    {"name": "Луизианская покупка", "type": "Событие"}
  ],
  "learning": {
    "properties": ["Год события", "Президент США"],
    "imageRecognition": false
  }
}
```

Это значение корневого `deck`.

- `members` — именно объекты, которые будут показываться новыми карточками.
- Президента, который является ответом на вопрос о событии, не включай автоматически в участники.
- `learning.properties` — **названия** изучаемых свойств. Опущенный список допускает более широкий охват; для предсказуемого пакета задавай его явно.
- `imageRecognition` разрешает изучение основных изображений. Это не переключатель отдельных фактов «Флаг».
- Пользователь может отключать свойства в интерфейсе. Пакет не должен создавать технические отметки «знаю», прогресс или приоритеты повторения.

Если пользователь должен учить и художников, и картины, включи обе группы в `members`, а свойства раздели по типам. Если он должен учить только картины, художников оставь справочными значениями.

## 19. Сборка с репозиторием Engi

Требуются Node.js 22.13+ и pnpm 10.30.1. Команды выполняются из корня репозитория:

```powershell
pnpm install --frozen-lockfile
pnpm pack:build ./my-pack ./artifacts/my-pack.engi
```

Для пакета v3 сборщик сам создаёт `manifest.json`, вычисляет SHA-256 и включает объявленные изображения. Обычно в исходной папке достаточно `bundle.json` и `media/`; не создавай manifest вручную и не оставляй там manifest от старого пакета.

Сборщик проверяет JSON-схему, семантические ссылки, неоднозначности внутри пакета, форматы изображений и ограничения архива. Любая ошибка означает, что результат нужно исправить и пересобрать.

Для проверки в приложении:

```powershell
pnpm dev
```

Открой `http://localhost:5173/engi/`, импортируй `.engi` через настройки и выбери колоду. Для безопасной проверки используй отдельный браузерный профиль или тестовую базу; не очищай личную базу пользователя.

## 20. Сборка без репозитория

Если доступен только Python или другой язык, можно собрать обычный ZIP самостоятельно. Формат manifest v3:

```json
{
  "format": "engi-pack",
  "schemaVersion": 3,
  "name": "Название пакета",
  "createdAt": "2026-10-13T12:00:00Z",
  "files": [
    {
      "path": "media/alabama-map.png",
      "bytes": 12345,
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "mime": "image/png"
    }
  ]
}
```

Значения размера и SHA-256 выше — **иллюстрации, не готовые данные**. Вычисляй их из реальных байтов. `createdAt` — фактическое время сборки в ISO 8601 с часовым поясом. Для пакета без изображений `files: []`.

Алгоритм:

1. Прочитай и проверь `bundle.json`.
2. Собери уникальные пути из `entities[].images[].file`.
3. Для каждого файла проверь путь, наличие, размер, расширение и сигнатуру PNG/JPEG/WebP.
4. Запиши в `files` фактический путь, размер в байтах, SHA-256 в нижнем регистре и MIME.
5. Создай ZIP с `bundle.json`, `manifest.json` и всеми объявленными изображениями. Не включай исходную папку целиком, временные файлы или сам архив внутрь архива.
6. Повторно открой архив: проверь пути, чтение JSON, наличие каждого файла, размеры и хэши.
7. Если есть доступ к приложению или его сборщику, обязательно выполни полноценную проверку импорта. Самостоятельная упаковка ZIP не заменяет семантическую проверку Engi.

Ограничения: итоговый архив и совокупный объём медиа — до 512 МиБ; каждый файл изображения и каждый JSON — до 16 МиБ; максимум 50 000 сущностей, 5000 определений свойств, 50 000 файлов manifest. Названия и алиасы — до 200 символов. Ограничения относятся к фактическим размерам, а не только к сжатому ZIP.

## 21. Проверка перед выдачей

Пройди все пункты:

- [ ] Архив действительно ZIP с расширением `.engi`; JSON в UTF-8.
- [ ] `schemaVersion: 3`, без технических ID и неизвестных полей.
- [ ] У каждого объекта и каждой ссылки есть `name` и `type`.
- [ ] Все свойства известны или объявлены; их типы, множественность и ограничения совместимы.
- [ ] В `deck.members` только нужные учебные объекты; справочные значения не добавлены случайно.
- [ ] `deck.learning.properties` содержит нужные свойства, в том числе изображения-свойства.
- [ ] Каждый доверенный факт проверен и имеет источник; непроверенное не объявлено проверенным.
- [ ] Названия короткие; длинные объяснения находятся в `description`.
- [ ] Прямые вопросы не дублируют заголовок; обратные вопросы естественные и корректные.
- [ ] Даты не содержат выдуманной точности; отсутствующие факты не заменены случайными ответами.
- [ ] Полнота многозначных списков действительно подтверждена.
- [ ] Изображения вложены, различимы, правильно принадлежат объектам; лицензии и источники реальны.
- [ ] Основные картинки и свойства-картинки разделены.
- [ ] Есть достаточно данных для желаемых механик, а не обещание принудительно показать их.
- [ ] Сборка завершилась без ошибок; ZIP повторно прочитан.
- [ ] Если импорт проверялся, результат сообщён честно, без преувеличения объёма проверки.

При повторном импорте названия, типы, алиасы и уточнения влияют на объединение с существующей базой. Не переименовывай всё ради «новой версии». Конфликт с уже установленными данными может потребовать выбора пользователя; это не повод выдумывать ID или обходить проверку. Настройки обучения и личные правки не обязаны перезаписываться обновлением пакета.

## 22. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Пакет не импортируется | Строгую схему, ID, типы ссылок, ZIP-корень, пути, хэши и реальные файлы |
| Свойство не предлагается учить | `learnable`, `verification`, источник, применимость `subjectTypes`, `deck.learning.properties` и пользовательские переключатели |
| Флаг не появляется отдельным свойством | Определение `image`, факт `value.file`, объявление файла у этого же объекта и включение в колоду |
| Карты и флаги путаются | `role: "property"`, `primary: false`, `recognition: false` у флага |
| Нет сопоставления или свайпов | Свойство `entity`, достаточные объекты и категории, разрешения форматов и текущую очередь обучения |
| Нет хронологии | `date` / `number`, минимум три разных подходящих значения, точность дат и включённый `sort` |
| Нет обратных вопросов | `learning.reverse`, краткость и пригодность значения, достаточные неверные варианты; неоднозначность может исключать самопроверку |
| Изучаются лишние люди или города | Состав `deck.members` |
| Слились разные одноимённые объекты | Типы, реальные алиасы, внешние ID и `qualifiers` |
| Текстовый девиз не спрашивается | Явное разрешение `choice` / `recallReveal`; длину и смысл ответа |

Заверши работу выдачей готового архива и короткого списка содержимого. Не обещай частоту заданий, число повторений или оценку памяти: это ответственность приложения, а не содержимого пакета.
