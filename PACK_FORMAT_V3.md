# Пакет знаний .engi, schemaVersion 3

Полная инструкция для передачи ИИ: [ENGI_PACK_AUTHORING_GUIDE.md](ENGI_PACK_AUTHORING_GUIDE.md). Ниже — краткий справочник формата.

`.engi` — ZIP с `bundle.json` и файлами `media/`. Новый `manifest.json` содержит `format: "engi-pack"`, `schemaVersion: 3`, `name`, `createdAt`, `files` (путь, размер, SHA-256, MIME). Builder заполняет manifest автоматически. `packId`, `packVersion` и внутренние ID в новом пакете не нужны.

## Правила

- У сущности и каждой ссылки обязательны `name` и `type`.
- Необязательное `entities[].description` — обычный текст до 4000 символов. Название остаётся коротким; описание открывается по ⓘ в новой карточке и заданиях. Это справочная информация, а не обучаемое свойство или штрафующая подсказка. Переносы строк сохраняются, HTML не исполняется. Повторный импорт обновляет описания из пакета, сохраняя пользовательские правки.
- Название, тип и алиасы — запрос на сопоставление, а не уникальный ключ.
- `aliases` содержат переводы и другие написания. `externalIds` — необязательные внешние каталожные идентификаторы, например `{"wikidata":"Q5582"}`.
- Для одноимённых объектов `qualifiers` содержит реальные свойства, например `{"Автор":{"name":"...","type":"Человек"}}`. Свойство должно быть известно или описано в `properties`.
- Объекты для обучения перечисляются в `deck.members` явно. Авторы, города и прочие справочные записи не становятся участниками сами собой.
- Новые поля объявляются в корневом `properties`: `name`, `aliases`, `valueType`, `multiple`, `learnable`; ограничения `subjectTypes` / `targetTypes` и вопросы необязательны.
- Название или изображение объекта показывается над вопросом. В `promptTemplates.forward` обычно достаточно «В каком году произошло это событие?» или «Кто автор этой работы?» без `{subject}`, чтобы не повторять заголовок. Авторские шаблоны сохраняются дословно; `{subject}` поддерживается, когда он действительно нужен по смыслу.
- Факт: `property`, `value`, `source` или `sources`, `verification`, необязательный `learnable`. Подтверждённый факт требует источника. Отсутствие источника допустимо только для непроверенного факта.
- `verification`: `unverified` по умолчанию; `direct`, `verified`, `user_confirmed` допускают обучение. Не указывайте эти статусы без проверки.
- Изображение: `file`, `role`, `sourceUrl`, `license`, необязательные `primary` / `recognition`. Файл PNG, JPEG или WebP обязан находиться в архиве.
- Для вопроса со всеми значениями многозначного поля сущность указывает `completeProperties: ["Автор"]`. Это утверждение о полноте списка; не ставьте его при частичном списке.

## Пример

### Расстановка по датам и числам

Для свойства с `valueType: "date"` или `"number"` задайте `learning.sort: "on"`.
Формат работает независимо от `learning.forward` и `learning.reverse`: оба можно
выключить, оставив только расстановку. Авторский вопрос задаётся в
`promptTemplates.sort`. Для даты поддержаны точные год, месяц и день; диапазоны
и приблизительные даты используются другими механиками и здесь исключаются.

Несколько значений у одного объекта допустимы при `multiple: true`. В расстановке
учитываются все записанные значения: объект с номерами 22 и 24 нельзя однозначно
расположить относительно объекта с номером 23, поэтому такая пара не включается
в одно задание. После проверки показывается полный список значений. Числа с
разными единицами измерения не смешиваются. Поле доступно в настройках колоды и
новой карточке; расстановка сама по себе не подтверждает память точных значений.

```json
{"name":"Порядковый номер","valueType":"number","multiple":true,"learnable":true,
 "learning":{"forward":false,"reverse":false,"sort":"on"},
 "promptTemplates":{"sort":"Расположите объекты по порядковому номеру."}}
```

## Пример пакета

```json
{
  "schemaVersion": 3,
  "name": "Моя колода",
  "entities": [
    {
      "name": "Винсент ван Гог",
      "type": "Человек",
      "aliases": ["Ван Гог", "Vincent van Gogh"]
    },
    {
      "name": "Звёздная ночь",
      "type": "Картина",
      "facts": [
        {
          "property": "Автор",
          "value": {"name": "Винсент ван Гог", "type": "Человек"},
          "source": {"kind": "manual", "name": "Проверить перед обучением"},
          "verification": "unverified"
        }
      ],
      "images": [
        {
          "file": "media/starry-night.jpg",
          "role": "artwork",
          "sourceUrl": "https://example.org/source",
          "license": "Укажите реальную лицензию",
          "primary": true,
          "recognition": true
        }
      ]
    }
  ],
  "deck": {
    "name": "Моя колода",
    "members": [{"name": "Звёздная ночь", "type": "Картина"}],
    "learning": {
      "properties": ["Автор"],
      "imageRecognition": true
    }
  }
}
```

Это образец структуры: URL и лицензию нужно заменить реальными, файл — добавить в `media/`. Готовые примеры без медиа находятся в `examples/`.

## Значения

| valueType | Формат value |
|---|---|
| image | `{"file":"media/flag-al.png"}` — файл объявлен в `images` того же объекта |
| entity | `{"name":"...","type":"...","aliases":["..."]}` |
| text | `"Текст"` |
| number | `123` либо `{"value":123,"unit":"см"}` |
| boolean | `true` / `false` |
| date | `1889`, `"1889"`, `"1889-06"`, `"1889-06-01"` |
| date, приблизительно | `{"value":1889,"approximate":true}` или `"circa 1889"` |
| date, диапазон | `{"start":1889,"end":1890}` |

`properties` внутри сущности может быть кратким словарём `{"Дата рождения":"1853-03-30"}`. Такие записи импортируются непроверенными; для обучения используйте расширенный `facts` с источником и реальным статусом проверки.

## Обратные вопросы

Для обучаемых текстовых, числовых, точных дат и ссылок на объекты приложение автоматически чередует «объект → свойство» и «значение → объект». Например, штат → год и год → штат. Старые пакеты менять не нужно.

Если значение встречается у нескольких объектов, остальные подходящие объекты исключаются из неверных вариантов. Обратная самопроверка доступна только для однозначного значения. При недостатке вариантов задание пропускается; приблизительные даты, диапазоны, логические значения и длинные тексты обратных вопросов не создают.

В описании свойства можно задать `promptTemplates.reverse` или отключить направление через `learning: {"reverse": false}`. Оба направления относятся к одному свойству в счётчиках, но ответы обновляют оценку памяти только проверенного направления.

Основные изображения при включённом `deck.learning.imageRecognition` также задаются в двух видах: изображение → название и название → выбор из четырёх изображений. Второй вид требует четырёх разных доступных изображений объектов одного типа; изображения свойств (например, флаги) в него не попадают. Оба вида используют общее знание об изображении объекта и не увеличивают число свойств в счётчиках.

## Сборка

```powershell
pnpm pack:build ./pack-source ./my-pack.engi
```

Лимиты: архив до 512 МБ, каждый файл / JSON до 16 МБ. Технические ключи `id`, `entityId`, `factId`, `valueEntityId`, `tagId`, `mediaId`, `deckId`, `packId` запрещены в декларативном содержимом. Внутренняя резервная копия сохраняет технические ID: это другой формат.

## Свойства с изображением

Тип `image` задаёт отдельное изучаемое визуальное свойство, например флаг или герб. Он требует обновлённой версии приложения. Определение: `{"name":"Флаг","valueType":"image","multiple":false,"learnable":true,"subjectTypes":["Штат США"]}`. Факт: `{"property":"Флаг","value":{"file":"media/flag-al.png"},"source":{"kind":"manual","name":"Личное знание"},"verification":"user_confirmed"}`.

Файл также объявляется в `images` этой сущности с лицензией и HTTPS-источником: `role: "property"`, `primary: false`, `recognition: false`. `recognition: false` исключает файл из общего узнавания объекта, но не отключает явное свойство-картинку. Добавьте «Флаг» в `deck.learning.properties`. Основное изображение карты остаётся `primary: true`, `recognition: true`.

Поддержаны одиночные свойства: узнавание объекта по значению-картинке, выбор картинки по названию и сопоставление. Эти форматы используют общее знание свойства; основная картинка объекта имеет независимый прогресс. В редакторе можно выбрать уже добавленное изображение или загрузить новое. Источник и статус проверки задаются так же, как для остальных фактов.

## Границы периодов

`date` принимает `{ "start": 1147, "end": 1149 }`. Импорт сохраняет точность каждой границы; полные даты не округляются до лет. Новое необязательное внутреннее поле `dateBoundaryPrecision` входит в резервные копии. Годовые периоды отображаются как `1147–1149`; варианты выбора могут отличаться началом, концом или обеими границами.

### Настройки упражнений с периодами

В `properties[].learning` необязательные `rangeBoundary` и `rangeBands` принимают `auto`, `on`, `off`. Первый управляет дополнением начала/конца, второй — полосами на общей шкале. `choice: off` также запрещает дополнение границы, `match: off` запрещает полосы. Для вопросов границ доступны необязательные `promptTemplates.rangeStart` и `rangeEnd`, например «Когда началась война?» и «Когда она закончилась?». Без шаблона приложение спрашивает нейтрально о начале/конце периода.

Новые упражнения допускают только точные закрытые диапазоны лет. Полные даты, приблизительные периоды и неизвестные границы не превращаются в точные годы автоматически. Обычный выбор полного периода остаётся доступным. `1900–1900` обозначает годовой диапазон, `1900` — одиночный год.

В задании с полосами могут смешиваться разные объекты и разные поля периода. Каждый вариант показывает название объекта и название конкретного свойства: «Джон Кеннеди / Президентство», «СССР / Период существования». Объект можно включить с несколькими периодами — это независимые факты, а не дубли объекта. Не создавайте отдельный объект «Президентство Кеннеди» только ради подписи задания.

Необязательное `properties[].shortName` задаёт короткую подпись поля, например `{"name":"Период нахождения на посту президента США","shortName":"Президентство","valueType":"date"}`. Если подпись не задана, используется полное `name`. Это оформление, оно не изменяет значение факта или прогресс. При повторном импорте подпись обновляется, кроме свойств с пользовательскими изменениями. Приложение не склоняет названия и не пытается угадать смысл кастомного поля.
