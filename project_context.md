# Энги — контекст проекта 3.0

Дата снимка: 2026-10-07. Полное описание реализации — `ARCHITECTURE_V3.md`. Формат генерации пакетов — `PACK_FORMAT_V3.md`. Обновление — `UPDATE_V3.md`.

## Стек и запуск

React 19 + TypeScript + Vite 8; локальный IndexedDB через Dexie, изображения в Cache Storage по SHA-256, FSRS через ts-fsrs, Workbox PWA. Node 22.13+, pnpm 10.30.1. `pnpm install --frozen-lockfile`, `pnpm dev`; URL `/engi/`. Сборка `pnpm build`, output `dist/`. GitHub Pages workflow сохранён.

## Версии

Приложение 3.0; база v4; декларативный пакет schemaVersion 3; полная резервная копия schemaVersion 3. Старые пакеты 1/2 сохраняют импорт по ID; старые резервные копии 1/2 читаются.

## Модель

- `entities`: один объект общей базы, постоянный внутренний ID, имя, тип, aliases, externalIds, summary. Название не уникально. Архивный объединённый дубль имеет mergedInto.
- `entityTypes`, `propertyDefinitions`: общие определения типов / свойств с алиасами и правилами обучения.
- `facts`: отдельные утверждения entity + property + typed value, sources, verification, точность даты, единица измерения, learnable. Ссылки valueEntityId образуют граф. Обратные связи вычисляются, не дублируются.
- `media`: объект, роль, основной файл, источник, лицензия, пригодность для обучения. Бинарные файлы дедуплицируются по SHA-256.
- `tags` / `entityTags`: тематические метки.
- `decks` / `deckMembers`: независимые явные подборки, настройки свойств, узнавания и исключения отдельных фактов. Общий прогресс между колодами.
- `learningState`: канонические единицы `ku:entity:<id>:visual_identity`, `ku:fact:<id>:forward/reverse`.
- `reviewEvents`: неизменная история со снимком вопроса и ответа, `targetMappings`: соответствия после миграций / объединения.

## Импорт v3

Пакет пишет человеческие имена, типы и алиасы; технические ID запрещены. Корень bundle.json: schemaVersion, name, properties, entityTypes, entities, deck. Каждый entity: name, type, aliases, facts, images, tags; для омонимов qualifiers. deck.members перечисляется явно.

`src/lib/engi/import/schema-v3.ts` проверяет формат; `semantic-merge.ts` разрешает ссылки и строит план. `src/services/declarative-pack.ts` проверяет архив и медиа, готовит просмотр и атомарно сохраняет после выбора. `ImportPreview` отображает совпадения, конфликты и выбор существующей колоды.

Совпадение: нормализованные имена / алиасы, тип и известные уточняющие сведения; близкие строки не склеиваются. При неоднозначности, архивном кандидате или противоречии нужен выбор. Все декларации разрешаются до фактов; неопределённая ссылка не привязывается к первой записи.

Совпавший факт сохраняет ID, добавляет источники. Конфликт одиночного значения: оставить / принять новое / сохранить спорным. Замена архивирует старый факт, создаёт новое знание. Импорт добавляющий, не удаляет отсутствующие записи. Точное повторное содержимое узнаёт ранее выбранную колоду, включая переименование. Изменения базы после предварительного просмотра отклоняют коммит.

## Обучение

Обычные вопросы выбирают только пригодные знания нужной колоды. Образы и форматы одного факта используют общую память. Обратный вопрос допускается только при однозначности.

Для нескольких ссылочных значений требуется явно полный набор: entity.completeProperties либо флаг полного набора в редакторе. Формат multi_choice проверяет отдельные факты, не спрашивает один произвольный правильный ответ. Исключённые из колоды значения не добавляются в варианты и не становятся дистракторами. Неполный многозначный набор хранится, но неоднозначный вопрос не генерируется. Текстовые / числовые многозначные задания пока не реализованы.

Неизвестная связь не равна отрицанию. Для полных наборов можно доказать отсутствие остальных значений; в остальных случаях генератор не создаёт задания «выбрать всё». Точные даты отображаются с сохранением точности; числа — вместе с единицей. Сортировка смешанных единиц и неточных дат ограничивается.

## Изменения и восстановление

Дубли объединяются через `EntityMergeDialog` / `entity-merge.ts`: переносятся факты, входящие ссылки, колоды, теги, медиа; сохраняются источники, история и осторожно объединённая память. Противоречия одиночных полей становятся спорными. Отмена объединения через восстановление предварительной копии.

Резервная копия v3 содержит весь граф, все доступные файлы, колоды, прогресс и настройки. Она восстанавливает внутренние ID, а не выполняет семантическое объединение независимых баз. Разные адреса браузера не синхронизируются автоматически.
