# Лента с памятью учебных целей: сервисный этап

> Исторический отчёт сервисного этапа. Подключение основной кнопки и интерфейса прогресса описано в `STUDY_CORE_GOAL_UI.md`; указание ниже о прежнем пути по умолчанию относится к состоянию до этого подключения.

## Что работает

Новый путь запускается через `createTrainerService(db).startGoalFeed(tag, format, mode)` или `startFeed(tag, format, mode, 'goals')`. Сессия и задания сохраняют `memoryModel: goals`, в том числе после возобновления.

В этом пути выбор заданий и коммит ответа используют `studyCore:memory:<goalId>`. Старые строки `learningState` используются только как временный каталог включённых/выключенных единиц и вход для существующего генератора. При ответе их расписание и статистика не изменяются. Контрактный сервис выполняет единственный FSRS-коммит памяти целей.

- Узнавание и воспроизведение одного факта имеют отдельные записи, сроки и счётчики.
- Полный набор имеет одну запись памяти. Ни правильный набор, ни частичный ответ не обновляют память отдельных членов.
- Новый первый ответ использует шаги FSRS из ядра: обучение `1m / 10m`, переобучение `10m`, retention `0.9`, fuzz выключен. Старую ручную лестницу новый коммит не вызывает.
- Первый неверный выбор обновляет новую память сразу. Квитанция первого ответа предотвращает повторный коммит при исправлении, выходе, замене сессии и повторной отправке.
- Раскрытый заранее ответ и свободная практика не создают независимого успеха и не меняют память целей.
- Событие результата содержит идентификаторы целей и их индивидуальные результаты. Определение цели сохраняется рядом с её памятью для дальнейшего интерфейса прогресса.
- Изменение ревизии даёт другой идентификатор цели; старые записи остаются историей. Полная миграция прежнего пользовательского прогресса не выполняется.

## Временный подбор заданий

`goalCandidates` компилирует варианты существующего генератора. Эквивалентные первичные цели в одной семье действий дедуплицируются, поэтому копирование одного варианта не множит представления этой цели.

`pickGoalFeed` проверяет сроки новых записей и паузу после действительного раскрытия. Старые сроки и bootstrap не определяют готовность. После фильтра допуска простое ранжирование учитывает просрочку и недавнее повторение объектов/форматов. Это рабочий подбор для проверки памяти, а не окончательный многомерный селектор.

Если доступны новые объекты, сохраняется существующее знакомство и бюджет открытия объектов. Если кандидаты отложены, возвращается `waitingUntil` с ближайшим сроком готовности. В новом пути нет старой очереди исправления «через четыре карточки»: следующая самостоятельная проверка следует сроку памяти и ограничениям раскрытия.

## Проверки

- Полный набор: **164 теста**, без ошибок и пропусков.
- **9 новых тестов** нового сервисного пути.
- Перебраны **все 16 подмножеств** четырёх вариантов полного набора. Во всех случаях создаётся одна запись памяти; успех только за точный полный набор; старые записи членов неизменны.
- Проверены отдельные recognition/recall, конкурентные первые ошибки, завершение исправления без второго коммита, игнорирование старых сроков, возврат ближайшего нового срока, раскрытие решения, ранний Recall, практика и отключение члена набора.
- Проверено, что 20 дополнительных копий одной конфигурационной строки не множат представления целей в пуле.
- Сохраняется предыдущий перебор 32 последовательностей событий первого ответа.
- `npm run build` проверяет TypeScript и production-сборку. Предупреждение о крупных чанках остаётся.

## Границы этапа

**Стандартная кнопка приложения всё ещё запускает прежний путь `startFeed` без четвёртого аргумента. Новый путь готов на уровне сервисов и тестов, но не включён по умолчанию в интерфейсе.** Старые страницы прогресса, показатели объектов и главный экран читают прежнюю память: включать новую ленту для них без совместного изменения было бы некорректно.

`waitingUntil` ещё не отображается существующим экраном остановки. Для нового пути интерфейс должен показывать ожидаемый следующий шаг и позволять обновить доступность без открытия дополнительных объектов. Следующий этап — подключить этот путь вместе с правдивым отображением памяти и ожидания.

Это ещё не готовый дневной план. Дневной счётчик здесь остаётся счётчиком самостоятельных попыток, а не уникальных закрытых обязательств по целям. Показатель прироста старой стабильности не используется для новых целей.

Групповое соотнесение с частично наступившими сроками не реализовано в новом подборе. Пригодность текущих кандидатов проверяется по всем первичным целям; полноценные группы и явные отношения порядка требуют своего генератора. Sort/timeline/missing остаются диагностической практикой.

Формирование кандидатов пока использует существующий генератор и проход по включённым единицам; производительность на больших графах не доказана. Не завершены охват раскрытий в свободных текстах, очистка журнала и политика обязательных/дополнительных целей. Браузерная проверка нового пути не выполнена: Chromium отсутствует. Моделирование не подтверждает эффективность запоминания или интересность ленты.
